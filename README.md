# 🎛️ Guitar Effects Lab · 音频效果器可视化实验室

用眼睛看见声音：频谱、波形、泛音，以及 Drive / EQ / Chorus / Delay 等效果器的变化。
前端使用 HTML、Web Audio API 和 Canvas，实时音频在浏览器本机处理。

**在线试玩：** [打开效果器](https://luceralex.github.io/guitar-effects-lab/)（Chrome 或 Edge 推荐；
麦克风需要浏览器授权）。在线版可用内置音源、音频文件、麦克风/电吉他及实时效果；
「深度分析」依赖本地 Python 服务，因此仅在本地版显示。

第一次使用：打开试玩页，点击 A4 音符即可听到内置音源；也可以选择自己的音频文件。
接电吉他时，选择「麦克风 / 电吉他」，在「输入」选线路输入或音频接口并点击「连接」，
在「输出」选择想用的扬声器或音频接口。先把监听音量调低，再逐渐调高。

**已知限制：** 普通电脑线路输入与 USB 音箱之间的浏览器往返可能有明显延迟，当前接法曾
听到约 0.1 秒延迟。这个项目适合试音色和观察效果，不能保证专业实时演奏手感。

## 快速开始

### Windows 本地版

双击 `启动效果器.bat`。若未安装依赖，先在本目录运行：

```powershell
python -m pip install -r requirements.txt
```

### 命令行

```bash
python -m pip install -r requirements.txt
python server.py
```

浏览器打开 `http://127.0.0.1:8765/`。Python 3.10+。服务在页面关闭后仍保留 10 分钟，
方便重新打开；若已退出，重新运行启动脚本。也可把静态文件放到任意 HTTPS 静态站点。

若双击启动失败，检查本目录的 `guitarlab.log`，或运行 `python server.py` 查看错误。
启动脚本的健康检查直接连接本机，不经过 HTTP 代理。

实时试音不依赖 Python；本地深度分析需要 `fastapi`、`uvicorn` 和 `numpy`。
不建议直接双击 `index.html` 来使用吉他输入，因为浏览器对本地文件的录音权限支持不一致。

## 架构：前端展示 / 后端计算

```
┌─ 前端（浏览器）────────────────────┐   ┌─ 后端（Python · FastAPI）────────┐
│ 实时链路（对延迟敏感，留在本地）：   │   │ 计算密集的离线分析：              │
│  采集/内置音源 → Web Audio 效果链   │   │  全曲 STFT 频谱图（numpy）        │
│  （独立音频线程，零网络往返）        │   │  逐帧基频跟踪 + 八度纠错（numpy）  │
│  自研 FFT 频谱（每帧 <1ms）         │   │  RMS/峰值包络 · THD · 频段统计     │
│  Canvas 渲染                        │   │                                   │
└──────────────┬─────────────────────┘   └──────────────▲────────────────────┘
               │  深度分析：解码 PCM（Int16）POST ────────┘
               │  ← JSON 结果（频谱图矩阵/曲线/统计）—— 前端只负责画
```

**为什么实时效果链不进后端**：弹琴到出声这条路径对延迟很敏感；若再把音频传给 Python
处理，会增加往返延迟。Web Audio 的大部分节点处理在浏览器音频线程中运行，频谱显示与
Gate/Wah 的包络跟随仍依赖页面更新。全曲分析交给后端。

## 它能回答你的问题

**为什么小提琴和钢琴拉同一个 440Hz，音色完全不同？**

音高由基频（440Hz = A4）决定，音色由泛音（谐波）结构决定。频谱上 440Hz 只是第一根峰，
小提琴和钢琴在 880 / 1320 / 1760 Hz…（第 2、3、4 次谐波）处的峰完全不同：

| | 泛音结构 | 时间行为 |
|---|---|---|
| 小提琴 | 约 1/k 递减，接近锯齿波的谱 | 稳态持续 + 5~6Hz 揉弦（频率微动） |
| 钢琴 | 高次更亮，且略"非谐"（第 k 峰比 k·f0 稍高） | 整体指数衰减，高次谐波衰减更快 |

页面内做了两件事来展示这一点：

1. **内置乐器是加法合成**——小提琴/钢琴的每个谐波都是代码里逐条画出来的正弦振荡器
   （见 `audio-engine.js` 的 `_buildVoice`），"音色 = 泛音组合"直接写在代码里；
2. **频谱视图带 f0 / H2…H8 谐波标记**，按住 A4 就能读出两件乐器各自的"泛音指纹"。

## 界面导览

```
┌─ 顶栏：信号源（内置音源 / 音频文件 / 麦克风）· 音色选择 · 音量 · A/B 旁路 ─┐
├─ 三个可视化标签：频谱（FFT）｜波形（时域）｜频谱图（时间滚动）              ┤
├─ 读数条：基频 f0 · 音名 · RMS 电平 · 谐波失真 THD · 采样率                  ┤
└─ 效果器机架：Gate → Wah → Comp → Drive → EQ → 调制 → Delay → Reverb         ┘
```

- **频谱**：横轴频率（对数）、纵轴 dB。叠加显示输入/输出对比、EQ 频响曲线（蓝虚线）、
  峰值保持（金线，用它"记住"关效果前的频谱形状）、谐波标记（绿线）。
- **波形**：示波器视图，带过零触发；红虚线是 ±1 削波界限。开 Drive 看平顶波最直观。
- **频谱图**：时间向左滚动，纵轴频率、颜色=能量（纸白 → 深褐，老照片式）。
  Delay 的回声条纹、Chorus 的频率"发胖"、钢琴的衰减轨迹都在这里看。

## 效果器原理速查

| 效果器 | 一句话原理 | 频谱上看到什么 |
|---|---|---|
| Drive | tanh 软削波 → 波形变方 → 新增谐波 | 正弦的 1 根峰 → 一排峰；THD 飙升 |
| EQ | 三段滤波器直接改各频段增益 | 频谱整体形状被搬动，紫虚线 = EQ 曲线 |
| Chorus | 副本经 LFO 调制的 ~20ms 延时 → 频率微漂 → 拍频变厚 | 单峰被抹宽 |
| Delay | 副本延迟 + 反馈 → 回声序列 | 频谱图的平行回声条纹 |
| Compressor | 超阈值部分按比率压下 → 动态变小 | 卡片 GR 表实时显示压了多少 dB |

### 信号流

```
[音源] ─> sourceBus ─┬─> preAnalyser（输入侧分析，静音假负载）
                     └─> Gate → Wah → Comp → Drive → EQ → 调制 → Delay → Reverb
                           └─> postAnalyser ─> 音量 ─> 扬声器
```

可视化独立于监听音量；`preAnalyser` / `postAnalyser` 的对比就是"效果器做了什么"。

**关于 DSP 内核**：频谱不是用浏览器内置的 FFT 画的——`dsp.js` 从零实现了
加窗 → FFT → 归一化 → 峰值/谐波分析的完整流水线，每帧对 4096 点时域数据跑一遍，
方便你逐行读懂每一步的数学。

## 建议的实验路线

1. **听出"泛音"**：正弦波按 A4 → 只有 1 根峰（没有音色）；切小提琴再按 → 一排峰。
2. **理解"失真"**：正弦 + Drive 拉满 → THD 从 ~8% 冲到 ~44%，频谱长出整排新谐波。
   （方波 THD 理论值 ≈ 48%，实际削波很接近）
3. **音色整容**：小提琴 + EQ 高频 +12dB → 高次谐波抬高 → 音色变亮。
4. **看见回声**：Delay 300ms / 反馈 50% → 频谱图看条纹，波形看重复脉冲。
5. **合唱的厚度**：Chorus 深度拉满 → 频谱峰变宽；用"A/B 旁路"对比开/关。
6. **分析真实音乐**：拖入任意 MP3/WAV，用 EQ 找人声频段（约 300Hz–3kHz）。

## 音色组合（经典机架预设）

机架头部的"音色组合"下拉内置 8 个大牌机架的经典配置（应用后可继续微调，改动自动
存入浏览器本地，刷新即恢复；"重置"清空记忆回出厂默认）：

| 组合 | 灵感来源 | 链路要点 |
|---|---|---|

| 德州蓝调 · Tube Screamer | Ibanez TS | 中频推挤过载 + slap 短延迟 + 弹簧混响 |
| 英伦堆积 · Plexi | Marshall Plexi | 堆积过载 + 板式混响，无调制 |
| 高增益金属 · 5150 | EVH 5150 | 紧门限 + 高增益 + V 型 EQ + 大厅长尾 |
| 冲浪远征 · Surf | Dick Dale | 5Hz 颤音 + 大湿度弹簧混响 |
| 太空氛围 · Ambient | 后摇/氛围 | 深合唱 + 600ms 长延迟高反馈 + 大厅高湿度 |
| 放克律动 · Auto Wah | 自动哇 | 包络跟随扫频——弹得越狠哇得越高 |
| 迷幻漩涡 · Phase 90 | MXR Phase 90 | 四段移相 + 轻过载 + 弹簧混响 |

## 经典名曲音色

预设下拉的第二组是歌迷社区公开复刻的经典歌曲音色（细节以原曲录音为准，参数按公开
的设备访谈与乐手复刻经验整理）：

| 名曲 | 复刻要点 |
|---|---|
| Hotel California 前奏 | 老鹰乐队 12 弦琶音：压缩匀化 + 微合唱 + 200ms 瀑布回声 + 大厅 |
| Hotel California 尾奏独奏 | Felder/Walsh 双琴：轻过载歌唱 + **八分音符回声（74BPM = 405ms）** + 板式；门限放宽到 -65dB/释放 400ms 保住长音尾 |
| Sultans of Swing | Knopfler 亮清音：轻压 + 高频提亮 + 90ms slap（不用拨片更像） |
| Comfortably Numb 独奏 | Gilmour：Big Muff 式失真 + 380ms 延迟 + 大厅 |
| Sweet Child O' Mine 前奏 | Slash 亮清音 + 100ms slap——练琶音的好模板 |
| Nothing Else Matters 前奏 | 清音琶音 + 合唱微湿 + 长厅混响 |

名曲预设里藏着的教学点：Hotel California 尾奏的回声时间不是随便设的——**405ms 正好是
74 BPM 的八分音符**，回声"跟拍"才有了原曲独奏的层次感。换成别的速度，把 Delay 的时间
改成 30000/BPM（毫秒）即可。

## 底噪治理（降噪门）

电吉他 USB 采集的底噪有三层：拾音器的 50Hz 电源哼声、声卡 ADC 的宽带嘶声、线路干扰。
机架第一位的**降噪门 Gate** 按吉他界的标准做法处理（GitHub 上 Faust/AudioWorklet
吉他效果器与电子管音箱模拟项目的共识方案）：

- **低切**（默认 80Hz）：吉他有效频段之下的隆隆声直接切掉
- **哼声滤除**（默认开）：50Hz + 100/150Hz 谐波陷波，Q=10 不伤低音 E
- **噪声门**：信号电平低于门限（默认 -55dB）→ 压掉 48dB；过门限 → 2ms 快开；
  松手按释放时间（默认 150ms）缓关。卡片上的电平表实时显示门的开合
- 调法：**不弹琴时看电平表**，把门限调到刚好在底噪之上（表变灰"关"）；弹琴时表变绿"开"

## 接电吉他（USB 声卡，如 JOYO Jam Buddy II）

Jam Buddy II 内置免驱 USB-C 声卡（OTG 音频接口），插上电脑就是一个标准录音设备——
浏览器用标准 `getUserMedia` 就能采集，**不需要任何专用驱动或插件**。

1. 用 USB-C 线把 Jam Buddy II 连上电脑（首次连接设备会自动安装驱动）；
2. 在 Jam Buddy 上调好音色；官方资料没有说明 USB 录音信号的精确取样点，不能保证它是纯干声；
3. 信号源选 **"麦克风 / 电吉他"**，在"输入"下拉里选 Jam Buddy（软件会自动预选名字里
   含 Jam / Guitar / 声卡 的设备），点**连接**并在浏览器弹窗里允许麦克风；
4. 机架上的 Drive / EQ / Chorus / Delay / Comp 现在全部作用于你的琴声，A/B 一键对比；
5. 连接后软件会尝试把处理后的声音送回 Jam Buddy；若页面提示切换失败，在"输出"下拉里
   手动选它，或将它设为 Windows 默认输出。浏览器必须支持 `AudioContext.setSinkId` 才能
   直接切换设备。

实际有两条可能同时出声的路径：

```
吉他 → Jam Buddy 输入 ─┬→ Jam Buddy 本机处理 → 自带扬声器（硬件直通）
                      └→ USB 录音 → 浏览器效果链 → USB 回放 → Jam Buddy 扬声器
```

软件只控制第二条路径，不能从浏览器关闭 Jam Buddy 的硬件直通。把**页面的音量**调到 0
再弹琴：若音箱仍出声，那就是硬件直通。再把页面音量打开、将 Delay 设得很明显；若听到
即时声和延迟后的处理声叠在一起，就是两条路径同时播放。浏览器往返延迟因设备和系统而异，
两路叠加可能造成回声或梳状滤波。软件已关闭浏览器的回声消除、通话降噪和自动增益。

在当前这台 Jam Buddy II 上实测：把 `GUITAR.VOL` 或当前音色的 `CH.VOL` 调到 0，
音箱吉他声消失时，网页输入频谱也停止跳动。两个旋钮都不能只关闭本机吉他声、同时保留
USB 吉他输入。以当前“吉他插 Jam Buddy、同一台设备负责 USB 输入和输出”的接法，
无法只从其扬声器听到网页处理后的吉他声；打开网页监听会把处理声叠在本机声上。

若要只听软件效果，可用**独立的 Hi-Z 吉他音频接口**把吉他送进电脑，不把吉他插在
Jam Buddy 的吉他输入口；网页“输入”选该接口，“输出”选 Jam Buddy II。此时 Jam Buddy
只负责播放电脑返回的音频。该方案仍有浏览器和 USB 往返延迟，适合先试听验证手感。
把 Jam Buddy 调成 clean 不会消除现有两条路径之间的延迟。

### 吉他插电脑线路输入、Jam Buddy 负责输出

若使用吉他转 3.5 mm 线，把线插在电脑的 **Line In／线路输入**，不要再把吉他插在
Jam Buddy 的吉他输入口。保持 Jam Buddy 通过 USB 连接电脑。网页输入选
`线路输入 (Realtek(R) Audio)`，输出选 `扬声器 (JAM BUDDY II)`；连接后弹琴，
以输入频谱是否跳动确认收到了吉他信号。页面会优先选择检测到的线路输入。

电脑线路输入通常不是专用的 Hi-Z 吉他接口，可能出现电平低、音色发闷或噪声较大的情况；
若如此，使用带 Hi-Z／Instrument 输入的音频接口更合适。

若弹奏感觉明显慢于声音，先选「实时练琴 · 基础音色」与现有音色比较。它关闭噪声门、调制、
Delay 和 Reverb，保留轻过载与 EQ，便于区分效果尾音和设备往返延迟。页面会请求较短的
录入／播放缓冲，并显示浏览器报告的部分延迟；这些读数不等于完整的弹弦到扬声器延迟。
电脑线路输入与 Jam Buddy USB 输出是两台独立音频设备，实际延迟还受各自驱动和 Windows
缓冲影响；网页无法保证达到专业声卡配合原生低延迟驱动的实时监听手感。

## 常见问题

- **没有声音？** 先点击任意按钮/音符（激活音频上下文）；检查音量滑杆。
- **识别不到 Jam Buddy？** 确认 Windows「声音设置 → 输入」里出现了它的录音设备；浏览器
  授权弹窗要点"允许"；页面需通过 localhost / https 打开（直接双击 file:// 不支持采集）。
- **声音"关不掉"？** 音符按钮/键盘是"按住发声、松手即停"；按 **Esc** 或点 **"全停"**
  会停止软件中的音符、音频文件、麦克风连接和噪声。Jam Buddy 本机的吉他直通不受网页控制；
  效果器里的 Delay/Reverb 尾音也可能再衰减一小段时间。
- **频谱不动？** 标签页切到后台时动画会降频（120ms 兜底刷新），回到前台即恢复 60fps。
- **麦克风打不开？** 使用在线 HTTPS 地址或 `python server.py` 打开的 localhost 地址，
  并在浏览器授权录音。
- **THD 读数在无效果时也不为 0？** 正常：窗函数泄漏、压缩器的轻微非线性、合唱的
  调制边带都会贡献几个百分点；正弦基线一般在 10% 以内。
